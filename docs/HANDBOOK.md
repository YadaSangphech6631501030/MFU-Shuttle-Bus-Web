# MFU Shuttle Bus System Handbook

อัปเดตตามโค้ดวันที่ 23 กันยายน 2026 คู่มือนี้อธิบาย User Web, Admin Web และการดูแลระบบปัจจุบัน เมนูผู้ใช้เป็น Feedback แบบประเมิน ไม่ใช่ระบบส่งและติดตามสถานะ Report เดิม

## 1. ภาพรวมระบบ

ระบบ MFU Shuttle Bus แบ่งเป็น 3 ส่วนหลัก

- `frontend-vue/` เว็บ Vue 3 สำหรับผู้ใช้ทั่วไป
- `admin-web/` เว็บผู้ดูแลระบบ
- `backend-node/` Backend API และฐานข้อมูล MongoDB

ผู้ใช้ทั่วไปดูเส้นทางรถ เลือกสถานีต้นทาง/ปลายทาง บันทึกสถานีโปรด และให้คะแนน Feedback ส่วนผู้ดูแลใช้ Admin Web ดู Dashboard/GPS จัดการสถานี เส้นทาง กล้อง ระดับจำนวนคน บัญชีผู้ดูแล และอ่าน Feedback

เปิด User Web หรือ Admin Web ตาม URL ที่ทีมให้ ผู้โดยสารไม่ต้องล็อกอิน ส่วน Admin ต้องมีบัญชีที่ได้รับสิทธิ์

เอกสารประกอบสำหรับเตรียมสอบและส่งมอบ:

- `docs/projectmap.md` แผนที่โครงสร้างโปรเจกต์
- `docs/prd.md` Product Requirements Document
- `docs/agent.md` System/agent architecture
- `docs/er.md` ER/logical relationship
- `docs/data.md` Data dictionary
- `docs/HANDOVER.md` Checklist ส่งมอบ
- `docs/DOCKER.md` คู่มือ Docker

## 2. คู่มือผู้ใช้งานแอป

### 2.1 หน้า Home

หน้า Home ใช้สำหรับดูแผนที่รถ shuttle bus และเลือกเส้นทาง

วิธีใช้งาน

1. เปิดแอป MFU Shuttle Bus
2. กดช่อง `From station` เพื่อเลือกสถานีต้นทาง
3. กดช่อง `To station` เพื่อเลือกสถานีปลายทาง
4. ระบบจะแสดงเส้นทาง เวลาโดยประมาณ และข้อมูลรถที่ใกล้สถานีต้นทาง
5. กดปุ่มสลับภาษาเพื่อเปลี่ยนระหว่าง EN และ TH

หมายเหตุ

- แผนที่ถูกจำกัดให้อยู่ในพื้นที่มหาวิทยาลัยแม่ฟ้าหลวง
- ระบบไม่อนุญาตให้เลือกต้นทางและปลายทางเป็นสถานีเดียวกัน
- ปลายทางและคำแนะนำขึ้นกับสายที่เปิดอยู่ รูปเส้นทาง และทิศทางในข้อมูลปัจจุบัน ไม่ใช่รายชื่อปลายทางตายตัว
- หากแนะนำจุดขึ้นหรือลงรถต่างจากสถานีที่เลือก ให้อ่านชื่อป้ายและคำแนะนำให้ครบ ระยะ straight-line เป็นระยะเส้นตรง ไม่ใช่ระยะเดินจริง
- กดรูปรถเพื่อดูเลขรถ สถานีปัจจุบัน/ถัดไป และกดพื้นที่อื่นเพื่อปิดป๊อปอัป กดหมุดสถานีเพื่อดูเวลารอ จำนวนคน และระดับสถานะ
- Unavailable หมายถึงยังประเมินเวลาไม่ได้ ไม่ได้ยืนยันว่าไม่มีรถ ให้ตรวจความสด GPS และเงื่อนไขทริป

### 2.2 Favorite Stations

หน้า Favorite Stations ใช้สำหรับบันทึกสถานีที่ใช้บ่อย

วิธีใช้งาน

1. เปิดเมนู Favorite Stations
2. กด `Add new`
3. เลือกสถานีที่ต้องการบันทึก
4. สถานีโปรดจะแสดงอยู่ด้านบนของรายการค้นหาในหน้า Home
5. กดไอคอนถังขยะเพื่อลบสถานีโปรด

เพิ่มหรือลบรายการโปรดผ่านหัวใจบนป๊อปอัปสถานีได้ด้วย รายการเก็บในเบราว์เซอร์เครื่องนั้น ไม่ได้ซิงก์ข้ามอุปกรณ์

### 2.3 Bus Stations

หน้า MFU Transit / รายการสถานี แสดงสถานีแยกตามสายรถ

วิธีใช้งาน

1. เปิดเมนู MFU Transit / รถรับส่ง มฟล.
2. กดหัวข้อสายรถเพื่อขยายหรือยุบรายชื่อสถานี
3. กดไอคอนบ้านเพื่อกลับหน้า Home

### 2.4 Feedback / ข้อเสนอแนะ

หน้าปัจจุบันเป็นแบบประเมินความพึงพอใจ ไม่มีตัวเลือกประเภทเหตุการณ์หรือช่อง Location/Describe the problem

1. เปิดเมนู **Feedback / ข้อเสนอแนะ**
2. กรอกชื่อและอีเมลให้ถูกต้อง
3. ให้คะแนน 1–5 ดาวครบทั้งห้าหัวข้อ: การบริการที่สถานี สภาพรถรับส่ง มารยาทและความปลอดภัยในการขับรถ ความสุภาพของพนักงานขับรถ และความพึงพอใจโดยรวม
4. กด **Submit / ส่งข้อเสนอแนะ** แล้วรอข้อความสำเร็จ ไม่กดส่งซ้ำระหว่างรอ
5. เมื่อสำเร็จระบบล้างฟอร์มให้ หากยังมีกรอบเตือนให้แก้ชื่อ อีเมล หรือคะแนนที่ไม่ครบก่อนส่งใหม่

แบบประเมินนี้ไม่ใช่ช่องทางแจ้งเหตุฉุกเฉิน ให้ติดต่อเจ้าหน้าที่ตามช่องทางที่มหาวิทยาลัยกำหนด

### 2.5 เมนูและภาษา

เมนูด้านข้างปัจจุบันมี MFU Transit, Favorite Stations และ Feedback กด **TH | EN** บนหน้า Home เพื่อเปลี่ยนภาษา ส่วน Settings ที่ตั้งระดับจำนวนคนเป็นเมนูของ Admin Web

## 3. คู่มือผู้ดูแลระบบ Admin Web

### 3.1 เข้าสู่ระบบ Admin

1. เปิด Admin Web
2. เข้าสู่ระบบด้วยบัญชีผู้ดูแล
3. เมื่อเข้าสู่ระบบสำเร็จจะเข้าสู่ Dashboard

ขอบัญชีจากผู้ดูแลของสภาพแวดล้อมนั้น ไม่ใช้บัญชี demo กับระบบจริง เมื่อเลิกใช้งานกดรูปบัญชีมุมบน → Log out

### 3.2 Dashboard

Dashboard ใช้ดูภาพรวมระบบ

ข้อมูลหลัก

- จำนวนผู้โดยสารที่รออยู่
- จำนวนรถที่ online
- การ์ดสรุปอื่นตามหน้าจอ (ดูหมายเหตุข้อมูลเก่าด้านล่าง)
- แผนที่สถานีแบบ live station map
- Crowd alerts
- Dispatch guide

กดกระดิ่งเพื่อดูสถานีที่ต้องให้ความสนใจ สีและชื่อระดับจำนวนคนอ้างอิง Settings ไม่ใช่สีที่กำหนดตายตัว

**ส่วนเก่าที่ยังอยู่ในโค้ด:** Dashboard ยังมีการ์ด Pending reports นับข้อมูลเหตุการณ์เดิมที่ไม่ใช่ Feedback ไม่ใช่จำนวนแบบประเมิน และไม่มีเมนูติดตามงาน Report ให้ใช้งานในหน้าปัจจุบัน คู่มือนี้จึงไม่ให้ขั้นตอนเปลี่ยนสถานะงานจากการ์ดดังกล่าว

### 3.3 Station Setting

หน้า Station Setting ใช้จัดการข้อมูลสถานี

การเพิ่มสถานี

1. กด `Add station`
2. กรอก Station ID ไม่ซ้ำ ชื่ออังกฤษ/ไทย และพิกัด หรือเลือกตำแหน่งบนแผนที่
3. เลือกสายรถที่ผ่าน
4. กดบันทึก

หากมีกล้อง ให้ใส่ Camera URL ที่ Backend เข้าถึงได้ และตรวจตำแหน่ง/สายของสถานีบน User Web หลังบันทึก

การแก้ไขสถานี

1. กด `Edit` ที่แถวสถานี
2. แก้ข้อมูลที่ต้องการ
3. กดบันทึก

การลบสถานี

1. กด `Delete`
2. ยืนยันการลบ

### 3.4 Station CCTV

เมนูปัจจุบันชื่อ **Station cameras** ใช้ดูภาพและควบคุม detector ของแต่ละสถานี

1. ตั้ง Camera URL ใน Station settings แล้วเลือกสถานีใน Station cameras
2. กด **Start detection** และรอภาพแรก กรณี RTSP เบราว์เซอร์อาจไม่เล่นโดยตรง ต้องรับภาพผ่าน Backend
3. กด **Draw detection area** แล้วลากกรอบสี่เหลี่ยมบริเวณคนรอ หรือเลือก **Full frame** เพื่อใช้ทั้งภาพ
4. กด **Save area** เพื่อบันทึก หรือ Cancel เพื่อยกเลิก ถ้า detector ทำงานอยู่ ระบบจะเริ่มใหม่เพื่อใช้ ROI ใหม่
5. เทียบจำนวนคนกับภาพจริงและตรวจ Dashboard/User Web กด **Stop detection** เมื่อต้องการหยุด

ROI คือพื้นที่ตรวจจับ ไม่ใช่ตัวเลือกตรวจเฉพาะศีรษะ การซ้อนทับ แสง และมุมกล้องยังมีผล หากไม่มีภาพให้ตรวจเครือข่ายกล้องและการติดตั้ง Python/YOLO

### 3.5 Buses

หน้า Buses ใช้ตรวจข้อมูลรถและความสด GPS ไม่ใช่ฟอร์มเพิ่ม/แก้รถด้วยมือ การจับคู่อุปกรณ์กับรถดู [GPS.md](GPS.md)

ข้อมูลที่แสดง

- รายการรถทั้งหมด
- สายรถ
- สถานะการเชื่อมต่อ อายุข้อมูลและเวลา GPS ล่าสุด
- ความเร็ว พิกัด และสถานะเคลื่อนที่/หยุด/ไม่ทราบ
- จำนวนรถแยกตามข้อมูลที่ระบบประเมิน รถหยุดไม่ได้หมายความว่า GPS หลุดเสมอไป

### 3.6 Feedback / ข้อเสนอแนะ

1. เปิดเมนู **Feedback** ใน sidebar
2. ค้นหาข้อเสนอแนะ ชื่อ หรืออีเมล และเลือกช่วงวันที่ตามต้องการ
3. อ่าน Rating overview และคะแนนเฉลี่ยรายหัวข้อ กราฟสรุปทุกรายการที่ผ่านตัวกรอง ไม่ใช่เฉพาะหน้าตารางที่กำลังเปิด
4. เปลี่ยนหน้าตารางเมื่อมีหลายรายการ แล้วกด **View details** เพื่อดูอีเมลและคะแนนแยกหัวข้อ
5. หากจำเป็นต้องลบ กดถังขยะ ตรวจข้อความยืนยันก่อนลบ เพราะเป็นการลบข้อมูลจริง

ไม่มีแท็บ Active reports/History, ตัวกรอง Category/Status หรือปุ่มเปลี่ยน Pending/In progress/Resolved ในหน้าปัจจุบัน ชื่อไฟล์ภายในยังเป็น `Reports.vue` แต่หน้าจอแสดงเฉพาะ Feedback

### 3.7 Admin Settings

ค่าที่ตั้งใช้ร่วมกันทุกสถานี ไม่ใช่การตั้งแยกสถานี

1. เข้าสู่ระบบ Admin แล้วเปิดเมนู Settings
2. กดไอคอนดินสอ **Edit** เพื่อแก้ชื่อสถานะ ช่วง **From–To** และสี เลือกจากช่องสีหรือพิมพ์ HEX 6 หลัก เช่น `#2eb85c`
3. กด **+ Add status** เพื่อเพิ่มแถว แล้วกรอกชื่อ ช่วงจำนวนคน และสี
4. กำหนด From ของแถวถัดไปให้มากกว่า To ของแถวก่อนหน้า หากแถวเดิมไม่จำกัดจำนวน ให้ใส่ To ก่อนเพิ่มช่วงต่อไป
5. กด **Save changes** และรอข้อความยืนยัน หรือกด **Cancel** เพื่อยกเลิกค่าที่ยังไม่บันทึก

ชื่อมีความยาว 1–60 ตัวอักษร ห้ามซ้ำกันโดยไม่แยกตัวพิมพ์ใหญ่/เล็ก และห้ามใช้ `unknown` ตัวเลขเป็นจำนวนเต็มไม่ติดลบ หน้าเว็บกำหนด To ให้มากกว่า From และเว้น To ว่างได้เฉพาะแถวสุดท้ายเพื่อหมายถึงไม่จำกัด
ช่วงรวมค่าที่ปลายทั้งสองด้าน เช่น 0–5 และ 6–9 สามารถเว้นช่องว่างระหว่างช่วงได้ แต่จำนวนคนที่ไม่อยู่ในช่วงใดจะเป็น `UNKNOWN` (นอกช่วงที่กำหนด) สีเทา

**ข้อจำกัดปัจจุบัน:** หน้าจอมีไอคอนถังขยะลบแถวในโหมดแก้ไข แต่ API ยังต้องมีสามช่วงหลัก `low`, `medium`, `high` และรองรับสถานะเพิ่มสูงสุด 20 รายการ การลบจนเหลือน้อยกว่าสามแถวจึงยังบันทึกไม่ได้ การลบหรือจัดแถวหลักใหม่ยังต้องทดสอบการจับคู่ชื่อ/ช่วงก่อนใช้งานจริง; ควรคงสามแถวหลักไว้และใช้ถังขยะกับสถานะที่เพิ่มต่อท้าย

สีและชื่อที่บันทึกจะใช้ในการแสดงสถานะของ Dashboard และ User Web หลังได้รับข้อมูลใหม่ MongoDB เป็นแหล่งเก็บค่าจริง ส่วน Supabase ใช้ส่งการเปลี่ยนแปลงให้ User Web

ตัวอย่างสามระดับ: Low 0–5, Medium 6–9 และ High ตั้งแต่ 10 โดยเว้น To ว่าง ไม่มี Very High ในตัวอย่างเริ่มต้นนี้

### 3.8 Routes

1. เลือกสายหรือกด **+ New line** กรอก Line ID ชื่ออังกฤษ/ไทยและสี
2. กด **Add points** แล้วคลิกแผนที่ตามลำดับที่รถวิ่ง จากนั้น Finish drawing
3. ลากจุดเดิมเพื่อแก้ตำแหน่ง หรือลาก midpoint เพื่อเพิ่มจุด ใช้ Undo/Redo และ Delete selected point ตามต้องการ
4. กด Fit route ตรวจทั้งเส้น ต้องมีอย่างน้อยสองจุดต่างกัน เลือก Show on passenger web แล้ว Save route
5. ตรวจการกำหนดสายของสถานีและลอง From–To บน User Web หลังบันทึก

Clear points ล้างจุดในร่างทั้งหมด ส่วน Delete line ลบสายที่เลือก ต้องอ่านคำยืนยันก่อนใช้ Import/Export GeoJSON ใช้รับส่ง geometry ซึ่งเรียงพิกัด `[longitude, latitude]`

### 3.9 บัญชีผู้ดูแล

1. กดรูปบัญชีมุมบน → **Profile Information** เพื่อเปิดรายการ Users (ไม่ได้อยู่ใน sidebar)
2. กด **Add administrator** กรอก username/email/password แล้วบันทึก ส่งรหัสผ่านผ่านช่องทางส่วนตัว
3. ลบบัญชีเฉพาะเมื่อยืนยันผู้ใช้ถูกคน และยังเหลือ Admin ที่เข้าใช้งานได้ ไม่ทดลองลบตนเองหรือ Admin คนสุดท้าย

หน้าปัจจุบันแสดง role เป็นข้อความ ไม่มีตัวเลือกแก้ role และไม่ได้เป็นฟอร์มเปลี่ยนรหัสผ่านส่วนตัว

### ข้อมูลรถแบบ Realtime

เปิดหน้าเว็บตามปกติ ไม่ต้องกดเปิด Realtime หรือเปิด Console เพื่อให้รถอัปเดต
ระบบโหลดข้อมูลเริ่มต้นจาก API และรับข้อมูลรถใหม่ผ่าน Supabase เมื่อเชื่อมต่อได้
หากการเชื่อมต่อหลุด ระบบใช้ API สำรองและโหลดข้อมูลใหม่เมื่อกลับ online
รถจอดอาจมีตำแหน่งเดิม แม้ระบบกำลังรับข้อมูลอยู่; ETA ขึ้นกับความสด ทิศทาง และความเร็ว GPS

User Web โหลดสถานี/เส้นทางผ่าน `/api/public-data` และรับจำนวนคน สี และชื่อสถานะผ่าน Realtime; Admin Web ยังโหลดข้อมูลสถานีผ่าน API เดิม ส่วน Feedback และ detector ยังใช้ API ตามรอบ
ตรวจเชิงเทคนิคที่ [REALTIME.md](REALTIME.md) และ [GPS.md](GPS.md)

## 5. การตรวจสอบก่อนใช้งานจริง

ควรทดสอบรายการต่อไปนี้ก่อนส่งมอบหรือ deploy

- Backend เปิดได้ที่ `http://localhost:5101`
- MongoDB เชื่อมต่อได้
- Admin Web เข้าสู่ระบบได้
- Dashboard โหลดข้อมูลได้
- ส่ง Feedback โดยกรอกชื่อ อีเมล และดาวครบห้าข้อ แล้วเห็นรายการ/รายละเอียด/คะแนนใน Admin
- เว็บผู้โดยสาร Vue เปิดแผนที่ได้
- เลือก From/To station แล้วเส้นทางขึ้นถูกต้อง
- เลือก From/To แล้วไม่เลือกสถานีเดียวกัน และคำแนะนำสอดคล้องกับเส้นทาง/ทิศทางที่ตั้งไว้
- แก้เส้นทาง สถานี หรือ Settings บนฐานทดสอบแล้วตรวจผลบน User Web
- เปลี่ยนภาษา EN/TH ได้ทั้งแอปและ Admin Web

## 6. ข้อควรระวัง

- ห้าม commit API key จริงหรือไฟล์ `.env`
- ถ้าเปลี่ยน backend URL ต้องแก้ทั้ง Admin Web และ เว็บผู้โดยสาร Vue
- ถ้าใช้มือถือจริง ต้องใช้ IP เครื่อง backend แทน `localhost`
- Google Maps ต้องเปิด API และใส่ key ให้ถูกต้อง
- ข้อมูลตัวอย่างใน Docker ใช้สำหรับ demo ไม่ควรใช้เป็นข้อมูลจริงใน production
- สำหรับเปิดใช้บน server จริง ให้ทำตาม [DEPLOY.md](DEPLOY.md) รวมการตรวจสิทธิ์และข้อจำกัดของโค้ดก่อนเปิดสาธารณะ
